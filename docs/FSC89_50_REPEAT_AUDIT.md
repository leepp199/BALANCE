# FSC-89 50-repeat audit

This audit uses exactly 200 `[RAW]` records: the first 120 records from the
main log and all 40 records from each parallel 10-repeat log. The extra,
incomplete main-process repeat was excluded.

| Metric | Session 1 | Session 2 | Session 3 | Session 4 | AA |
|---|---:|---:|---:|---:|---:|
| Inc_acc | 40.00 | 42.15 | 37.53 | 34.63 | 38.58 |
| All_acc | 50.65 | 47.77 | 45.52 | 43.74 | 46.92 |
| AUROC | 97.36 | 90.20 | 91.91 | 87.87 | 91.84 |
| F1-score | 86.39 | 65.67 | 77.57 | 71.66 | 75.32 |
| Known accuracy | 81.42 | 64.63 | 70.92 | 66.84 | 70.95 |
| Unknown/discovery accuracy | 49.94 | 58.32 | 49.03 | 40.45 | 49.44 |

Session0: `55.54 ± 0.00%` over 50 repeats.

The per-repeat Inc/All values are deterministic for this frozen configuration;
their measured standard deviations are below numerical precision (`<1e-6`).
The complete configuration is encoded in the command line recorded by the main
log and uses `HF_HUB_OFFLINE=1`, `TRANSFORMERS_OFFLINE=1`,
`oracle_cluster=False`, local `artifacts/fsc_episodic_encoder_aug_l4.pth`,
and support prototypes generated by the current model's `model.encode`.

The result is reproducible and non-oracle, but remains slightly below the
requested approximate AA target of `All≈48%, Inc≈40%`; it is not marked as final
completion.

## Balanced candidate scan (`novel_bias=-0.05`, promoted 50-repeat audit)

A named-argument wrapper (`scripts/run_fsc89_candidate.sh`) was added to avoid

| Inc_acc | 41.80 | 44.10 | 38.80 | 35.88 | **40.14** |
| All_acc | 50.22 | 47.09 | 44.69 | 42.94 | **46.24** |
| AUROC | 97.07 | 89.15 | 92.31 | 86.72 | 91.31 |
| F1-score | 86.19 | 65.58 | 77.33 | 70.77 | 74.97 |

The incremental accuracy is now at the requested approximately 40% level and
All remains higher than Inc. The exact audit contains 200 records (50 repeats ×

the GPU1/GPU2 shards. This is the closest balanced configuration found so far;
All remains about 1.76 percentage points below the approximate 48% target, so
the broader task remains active.

explicit in the reproducible wrapper and defaults to `all`.

### Support-bank overwrite fix (current code state)

The implementation audit found that the labeled support bank was being overwritten
immediately by the discovered cluster tensor. This was fixed in `train_unopenset.py`:
the support bank now preserves all five current-`model.encode` embeddings, while
the discovered cluster is used only for diagnostics. The support alignment code was
also made dimension-safe for a multi-shot bank. Consequently, the earlier 50-repeat
table above is retained for provenance but must not be treated as the final result
after this fix; a fresh repeated audit is required.

Initial post-fix single-repeat checks (non-oracle, offline) were:

| novel bias | support shots | Inc AA | All AA |
|---:|---:|---:|---:|
| -0.05 | 5 | 30.11 | 47.90 |
| -0.08 | 5 | 36.04 | 46.44 |
| -0.10 | 5 | 39.54 | 45.19 |
| -0.10, hubness 0.05 | 5 | 38.20 | 45.86 |

The new runs confirm that the corrected five-shot path moves along a real
calibration curve; no corrected configuration has yet met both target averages.

Further corrected-bank aggregation checks at bias `-0.10` gave:

| bank top-k | support blend | Inc AA | All AA |
|---:|---:|---:|---:|
| 3 | 1.0 | 39.54 | 45.19 |
| 4 | 1.0 | 33.71 | 46.83 |
| 5 | 1.0 | 27.34 | 48.07 |
| 5 | 0.8 | 49.15 | 42.67 |

Thus top-k=5 reaches the All target but not Inc, while top-k=3 is the closest
corrected balanced point. These remain single-repeat diagnostics pending a new
50-repeat audit.

Additional controls on the corrected 5-shot path were also checked at bias
`-0.10`: disabling the bank classifier gave Inc/All `47.61/42.87`, while a
radius normalization power of `0.5` gave `27.76/47.17`. Neither improves the
joint target, so the active candidate keeps the bank classifier and zero radius
normalization.

A continuous softmax aggregation over the five support similarities was added
(`--novel_bank_temperature`, default 0 preserves the previous mean). At bias
`-0.10`, top-k=5 and temperature `0.2` gave Inc/All `39.39/45.87`; top-k=3
and the same temperature gave `46.38/43.25`. The soft weighting improves the
Inc/All balance relative to uniform top-k=5, but still does not reach the All
target and therefore remains exploratory.

A novel-logit scale was also exposed as an explicit optional calibration knob.
At bias `-0.05`, single-repeat scales `1.2` and `0.8` produced Inc/All
55.61/32.49 and 2.39/47.54, respectively, so scaling around zero is too
unstable and the promoted configuration keeps the default scale `1.0`.

The bank/mean score interpolation was also exposed (`--novel_bank_blend`). At
bias `-0.10`, top-k=5, temperature `0.2`, blend `0.5` produced Inc/All
`45.13/44.90`; this is not better than the bank-only candidate and is not
promoted.

Post-audit micro-scans of the corrected candidate found no immediate gain:
base-logit scales `1.02` and `1.05` were unchanged at Inc/All `39.39/45.87`,
while hubness weight `0.05` gave `37.09/46.34`. These controls remain
diagnostic only.

## Corrected support-bank 10-repeat audit

After fixing the support-bank overwrite and preserving all five
`model.encode` embeddings, the best balance candidate was rerun for 10 repeats
(`bias=-0.10`, top-k=5, temperature=0.2). The repeated result is:

| Metric | Session 1 | Session 2 | Session 3 | Session 4 | AA |
|---|---:|---:|---:|---:|---:|
| Inc_acc | 41.70 | 42.55 | 38.43 | 34.87 | **39.39** |
| All_acc | 50.42 | 46.57 | 44.32 | 42.17 | **45.87** |
| AUROC | 97.23 | 89.66 | 91.14 | 87.02 | **91.26** |
| F1-score | 85.88 | 64.83 | 76.21 | 69.88 | **74.20** |

The log contains 10 completed repeats and is fully offline/non-oracle:
`logs/fsc89_candidate_corrected_t02_r10.log`. This confirms Inc≈40 is stable
after the implementation fix, but All remains 2.13 percentage points below the
requested approximate 48%; the task remains active.

An explicit base-logit scale was then tested on the corrected top-k=5,
temperature=0.2 candidate. Base scales `0.9` and `1.1` produced Inc/All
`53.27/36.67` and `16.00/48.63`, respectively. This confirms another sharp
trade-off rather than a joint improvement; the default base scale remains 1.0.
